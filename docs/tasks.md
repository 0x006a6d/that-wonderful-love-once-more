### 必ず含めるもの（コア）

これらが揃った状態を「縦切り完成」と呼ぶ。何があっても落とさない。

- 格闘戦闘とヒットストップ（手応えがなければゲームとして成立しない）
- 犯人3体と役割差

- エンディング4分岐の判定
- 冒頭とニュースによる物語構造

### 8/23 の関門で判断するもの

**8/23 に縦切りが完成していれば着手する。していなければ着手しない。** 上から順に積む。

|順|項目|見積|備考|
|---|---|---|---|
|1|SDFGI・ボリュメトリックフォグ・SSR|1時間|`WorldEnvironment` の設定のみ|
|2|軽量モードのトグル|1時間|上記3つを一括で切る bool ひとつ。**3段階のプリセットは作らない**|
|3|警察・第3幕の三つ巴|2.5日|`RunState` が後半の難易度に返る仕掛けは作品の中心|
|4|銃モード|2日|格闘との切り替え。カメラ・移動・アニメの3系統が絡む。モード連動の画面ルック（監視カメラ風⇔ボディカム風、`game-design.md` §6.1.1）もここに含む|
|5|スマホ動画の3D演出|1日|**8/24以降に着手すること。** レベルとキャラが揃う前に手を出すと作り直しになる|

### 着手しないもの

- **ラグドール** — VRMはボーン数が多く揺れものも含むため `PhysicalBoneSimulator3D` が素直に動く保証がない。時間が読めない一方、エンディングの死体配置は固定ポーズのほうが確実に画が作れる。得るものが少なく失うものが読めないため、コンテスト版では扱わない

- [x] プレイヤーがダウンしたときの扱い（実機で「殴られていると操作不能になる」報告を受けて仕様を決定）
    - **ゲームオーバーは作らない。倒れて 3 秒後に自力で立ち上がり、HP は全快する。** 失うのは時間だけ
    - 理由: エンディング4分岐にプレイヤー死亡が無く、`ENGAGEMENT → BREACH` が時間で進むため、遅れがそのまま「警察が近づく」代償になる。ゲームオーバー画面を作ると 8/24 以降の UI 枠を先取りすることにもなる
    - 犯人の強さ（1発12ダメージ / 1.78秒間隔 / 9発・約15秒でHP0）は現状維持。数値はすべて `@export`

**受け入れ条件**

- 犯人1体が接近してきて殴り合いになる
    - ヘッドレス検証は `tools/test_robber_ai.tscn` で 11 項目 PASS（8/14 実施）
    - **実機での目視確認は未実施。** 仮ステージ北西に `Robber1` を配置してある
